# drone-fly

Project-local guidance for Claude Code. `PROJECT_BRIEF.md` is the authoritative source for
architecture, stack, paths, and quality standards; this file records repo-level conventions the
dev-team needs that don't belong in the brief's structured frontmatter.

## Dev-team write authorizations

The dev-team's **developer** agent may write to production-code paths declared in
`PROJECT_BRIEF.md` (`paths.production` → `src/drone_fly/**`). In addition, the developer is
authorized to create and modify these repository-level paths, which sit outside `paths.production`
but are required for normal implementation work:

- `pyproject.toml` — project metadata, dependencies, and tool config (ruff, pytest, mypy).
- `scripts/**` — developer utility scripts (e.g. dev-time test-fixture generators). These are not
  runtime application code and are not part of `paths.production`.
- Root user-facing docs — `README.md` (and `CHANGELOG.md` if/when one exists) — for keeping
  user-visible behavior and docs in sync per the developer role's documentation rules.
- `.env.example` — template for required environment variables.
- `viz/**` — the static, dependency-free activation-playback viewer (HTML/JS/CSS). Not Python
  runtime code and not part of `paths.production`; it is a shipped web asset served/opened directly.
- `configs/**` — example/reference YAML run-configs for the CLI (`--config`). Shipped inputs, not
  runtime application code; committed so the documented example runs work as-is.
- `.gitignore` — repository ignore rules (e.g. ignoring generated per-run `training/**` output).
- `uv.lock` — the dependency lockfile, regenerated by `uv lock` when `pyproject.toml` deps change.
- `tests/fixtures/**` — committed **generated** test-data artifacts (e.g. `mcns_fixture.npz`,
  `mcns_fixture_meta.csv`, `mcns_fixture_soma.csv`, `FIXTURE_PROVENANCE.md`) produced by running
  the dev-time generator under `scripts/`. These are regenerated *data*, not hand-authored test
  *code*; the developer may (re)generate them by running the build script. Hand-written test code
  (`tests/**/*.py`) remains QA's exclusive scope.

The **QA** agent's write scope remains `paths.test` (`tests/**`, i.e. the `tests/**/*.py` test code
and any test-only helpers it authors) as declared in the brief, plus `.claude/allowed-commands.yaml`
per the standard dev-team protocol. QA does not regenerate `tests/fixtures/**` generated artifacts
(the developer does, via the build script) — QA reads them and recomputes fixture-derived constants.

No agent may write anywhere outside this repository, and none may touch the tooling workspace it
was launched from.
