# Use Case 75: Re-tune run-2 pointer-noise from UC-74 measurements (run2b) + off-axis trust guard

## Summary
UC-74 measured the live classic-OpenCV HUD pointer reader's real error on Liftoff Arena "04 - Infinity Loop" captures, and it diverges materially from the **provisional** pointer-noise model baked into `src/drone_fly/training/configs/student-liftoff-run2.yaml`: measured bias ≈ 0.00734 rad vs provisional `bias_sigma_rad: 0.05` (sim over-modelled bias), measured per-tick jitter ≈ 0.08503 rad vs provisional `jitter_sigma_rad: 0.03` (sim under-modelled jitter ~2.8×), and suggested tolerance ≈ 16.38° vs provisional `bearing_tol_deg: 20.0` (source of truth: `docs/harness/uc74-arena-pointer-calibration.json`). UC-74 also found the HUD pointer is a faithful projection only within `|az| ≲ 20–25°` and clamps toward the screen edge beyond ~±30–40° (error 15–75°), and that it is detectable on only ~52% of live frames. This use case delivers a **new `student-liftoff-run2b.yaml` variant** that overrides the run-2 pointer block with the measured sigmas/tolerance and a re-tuned dropout, adds a **configurable off-axis `|az|` trust guard** to the live reader so the reader and the noise model agree about where the pointer is reliable, and documents the retrain/export path. It is a values + reader-guard change only — **no obs-schema change (VERSION=3/DIM=65), no student↔teacher contract change, no retrain required to land it in-sandbox**. The actual CUDA retraining and the re-evaluation against the run-2 baseline run on the user's GPU machine (mirroring UC-74's deferred live parts). Depends on UC-74 (PR #81) being present.

## Acceptance Criteria
1. **New `run2b` variant (not an in-place edit).** `src/drone_fly/training/configs/student-liftoff-run2b.yaml` is added with `extends: student-liftoff-run2` and overrides **only** the `perception.pointer` block: `bias_sigma_rad`, `jitter_sigma_rad`, and `bearing_tol_deg` set to the UC-74-measured values (from `docs/harness/uc74-arena-pointer-calibration.json` → `suggested_bias_sigma_rad ≈ 0.00734`, `suggested_jitter_sigma_rad ≈ 0.08503`, `suggested_pointer_bearing_tol_deg ≈ 16.38`; round sensibly in the YAML) plus the re-tuned `dropout_p` (see AC2). Each overridden line carries an inline comment citing UC-74 + the report as provenance and is **not** labelled "provisional". The original `student-liftoff-run2.yaml` is left unchanged as the A/B baseline.
2. **Dropout re-tuned to reflect real availability.** `dropout_p` is raised from 0.1 toward the measured live-unavailability regime (~50% of frames have no pointer). Because `dropout_p` is *per-episode* while the ~52% detection is *per-frame*, the chosen value (and whether a per-tick availability parameter is the more faithful model) must be justified in the implementation — see Pitfalls. A comment records the reasoning and the source number.
3. **Off-axis trust guard in the reader.** `HudPointerReader` gains a configurable bearing-magnitude threshold (e.g. `max_bearing_az_deg`, resolved via `from_config`) that marks a detection **unavailable** (availability bit 0, zeroed bearing) when the computed `|az|` exceeds it, matching UC-74's off-axis-clamping finding. **Default is off/None** → fully backward compatible; existing configs/presets are unaffected until they opt in. The `liftoff_arena` preset (and/or the run2b-associated harness config) sets it to ~30°.
4. **Config loads and validates.** `student-liftoff-run2b` resolves and loads through the training config loader (strict overlay — the new keys are in-schema), i.e. `drone-fly train student --config student-liftoff-run2b …` parses without error; the harness config carrying `max_bearing_az_deg` loads through `pointer_reader_from_config`.
5. **No schema/contract change.** Student obs schema stays `VERSION=3` / `DIM=65`; no change to `build_student_obs`, the student↔teacher interface, or the sim truth-pointer path. This is a noise-values + reader-guard change only.
6. **Provenance guard + guard-behavior tests.** A test ties the committed run2b sigma/tolerance values to `uc74-arena-pointer-calibration.json` (they cannot silently drift from their measured source); a test asserts `run2b` loads and overrides exactly the pointer block over `run2`; and tests cover the `|az|` guard on/off and the boundary (a detection just inside the threshold stays available; just outside → bit 0), with default-off preserving current behavior.
7. **Retrain + export path documented, training deferred.** The retrain/export/fly recipe is written down — `drone-fly train student --config student-liftoff-run2b --device cuda [--resume]` → `drone-fly train export <run>` → fly with `--preset liftoff_arena`. The **actual CUDA retraining and the re-evaluation vs the run-2 baseline are user-side GPU follow-ups**, explicitly out of the in-sandbox scope for this use case.

## Potential Pitfalls & Open Questions
- **Ambiguity (dropout model)** — the ~52% figure is *per-frame* detection; `dropout_p` is *per-episode* (a whole episode flies with no pointer). Raising per-episode dropout is not the same as modelling ~50% per-tick availability. Open: pick a justified `dropout_p` (e.g. a modest raise) as a proxy, **or** introduce a per-tick availability parameter if the training noise model supports one. The analyst should resolve this against the actual run-2 noise-injection code rather than guess.
- **Assumption (exact values)** — the YAML should use the report's measured numbers (0.00734 / 0.08503 / 16.38), rounded for readability; the test, not the eyeball, enforces agreement with the report.
- **Risk (behavioral shift)** — higher jitter (~2.8×) + the off-axis guard + higher dropout will make the student rely *less* on the pointer and more on gate memory/detection. Whether net flight improves is an empirical question answered only by the user-side re-eval vs the run-2 baseline (deferred); this UC does not claim a flight-quality gain, only a faithful noise model.
- **Risk (guard ↔ FP-suppression interaction)** — `fp_suppress_pointer` consumes the same `ptr_body`; the new `|az|` guard must compose cleanly with it (a guarded-unavailable pointer should not trip the FP sub-gate inconsistently).
- **Risk (stacks on unmerged UC-74)** — UC-75 depends on UC-74 (PR #81), which is not merged to `main`. The base-branch decision (stack on `feat/uc-74` vs wait for #81 to merge, then branch from `main`) must be resolved when this goes to `develop` — the same situation UC-74 had with UC-70.
- **Edge case (default-off guard)** — the guard default MUST be off/None so every pre-existing config and preset behaves exactly as today; only `liftoff_arena` (and configs that opt in) enable it.
