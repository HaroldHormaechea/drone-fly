# Use Case 29: Partial-anatomy connectomes above the spectral cap must still provision positions

## Summary
After UC-27 + UC-28, recording-enabled training on a large pruned slice fails with a runtime error from `ActivationRecorder` (`src/drone_fly/record/recorder.py:~157-160`): *"Neuron positions could not be provisioned for this connectome: it exceeds the spectral-layout cap…"* (hit on a real 122,816-neuron slice). This is a bug. The slice **has real anatomy** (central neurons carry `somaLocation`, so the real soma sidecar is written), and UC-28 already places the soma-less peripheral afferents via **cheap schematic body clusters** (crc32-based, no eigendecomposition). Provisioning such a slice needs **zero** spectral compute — yet it is wrongly refused. Root cause: the large-connectome guard in `resolve_positions` (`src/drone_fly/record/coordinates.py:1205`) reads `if n > _spectral_cap() and _anatomy_coverage(compute_data, override=meta_map) < n:` and defers on **any partial** anatomy (`< n`). That `< n` condition is stale from UC-27, when the soma-less remainder needed the expensive spectral `np.linalg.eigh` fill; UC-28 replaced that with schematic placement, so the only genuinely expensive path (`_computed_positions`, coordinates.py:776/815) now runs **only when there is zero real anatomy** (no brain bbox to anchor a schematic body → `_schematic_body_coords` returns `None` → whole-slice spectral). The fix narrows the guard to defer **only when anatomy coverage is zero** (`== 0`) and `n > cap`; a partial- or full-anatomy connectome provisions normally (real soma coords + schematic body placement) at any size, no spectral, no deferral. Scope is the guard condition + the deferral/recorder wording + tests + docs; no change to training dynamics, observation schema, connectome graph, reward, or checkpoints; all UC-27/UC-28 behavior preserved; hermetic CI stays green and offline.

## Acceptance Criteria
1. **Partial anatomy above the cap provisions (regression):** a connectome with `n > _spectral_cap()` that has ≥1 real soma plus soma-less afferents provisions successfully — real soma coords for soma-bearing neurons, schematic body placement for the soma-less, `display3d` finite for all `n` — with **zero** spectral-eigendecomposition calls (spy on `_spectral_embedding`/`_computed_positions` == 0), **no** deferral, and `_positions.csv` written.
2. **Recording-enabled training no longer raises:** constructing `ActivationRecorder` / running a recording-enabled train on such a partial-anatomy above-cap connectome does not raise the "exceeds the spectral-layout cap" error; it provisions and proceeds.
3. **Zero-anatomy case preserved (still unsupported at scale):** a connectome with **zero** real anatomy AND `n > cap` still defers with a WARN, attempts **no** eigendecomposition, and the recorder still raises its clear guidance error (prune first / provide anatomy). Verified by test.
4. **Small connectomes unaffected:** `n <= cap` behaves exactly as before in every anatomy state (anatomical / partial / none) — regression preserved.
5. **`DRONE_FLY_SPECTRAL_MAX` still works** as an escape hatch but is no longer required for partial-anatomy connectomes.
6. **Wording updated:** the deferral warning and the recorder raise message describe the true remaining condition (**zero** anatomy at scale), not "partial".
7. **Scope containment + CI:** no change to training dynamics, observation schema/width, connectome graph, reward, or checkpoints; UC-27/UC-28 behavior preserved (anatomy precedence, sidecar round-trip, self-heal, determinism, honesty `coords3d` real-or-None, full-coverage `display3d`, brain-scale guardrail); full suite (`ruff check .`, `ruff format --check .`, `uv run pytest`) green and offline; `node --check viz/viewer.js` still passes.

## Potential Pitfalls & Open Questions
- **Edge case (anatomy matches zero of this connectome's ids):** even with a non-empty tier-0 map, if none of its bodyids intersect this connectome, `_schematic_body_coords` returns `None` → whole-slice spectral. The guard's coverage check must reflect *effective* coverage of this connectome's ids (the same coverage `provision_positions` will see), so a zero-effective-coverage above-cap connectome still correctly defers (do not merely check `meta_map` non-empty). Align the guard's `_anatomy_coverage(...)` with the branch `provision_positions` actually takes.
- **Assumption:** `_anatomy_coverage(compute_data, override=meta_map)` already returns the count of neurons that resolve to a real soma for this connectome (0 ⇔ `provision_positions` would fall to `_computed_positions`); the fix keys off that.
- **Risk (message drift):** the warning/recorder text and the guard condition must stay consistent (both keyed on zero anatomy) so they can't diverge again — assert the wording in a test.
