# Use Case 38: Decouple no-progress / timeout early-termination from the crash penalty

## Summary
UC-37 (floor start + airborne survival reward) fixed the "no learning signal" failure — the value function now learns and entropy/std fall instead of diffusing — but training still converges to a non-flying policy (0% success, `ep_rew` pinned near −105 at `ep_len` ≈ 101). Root cause, confirmed from the code: a floor-sitting or non-progressing drone is cut by the UC-25 **no-progress ("stuck") detector** at `stuck_window` (100) steps, and `racing_env.py` folds *every* early-termination cut into `crash = True`, so the cut eats the full `collision_penalty` (100). The episode therefore scores `−time_penalty×steps − collision_penalty` ≈ −5 − 100 = **−105**, identical to a genuine floor/ceiling crash. Under UC-37's survival regime this is self-defeating: "stayed airborne but ran out of time / stopped progressing" is punished exactly like "smashed into the floor," so the +0.1/step airborne survival differential (≈ +10 over a 100-step hover) is swamped by the −100 terminal penalty and the takeoff gradient collapses. This UC **decouples the no-progress/timeout early-termination cut from the collision penalty**: a stuck/timeout truncation ends the episode without applying `collision_penalty`, while *genuine* floor / ceiling / out-of-bounds collisions (raw `state.collided`, not a controlled dock) keep the full −100 exactly as today. The grounded detector's treatment is a documented decision point (see AC-3). This restores a clean, positive gradient for takeoff-and-stay-airborne (hover 100 steps → ≈ +5 vs sit → ≈ −5) without weakening the crash / floor-shortcut ordering, and without rewarding loitering (completion +100 still dominates the ≤ +5 bounded loiter). A small exploration bump (`ent_coef` 0.0 → 0.01) is included to help the policy discover takeoff before exploration decays.

## Acceptance Criteria
1. **No-progress / timeout cut carries no collision penalty.** When an episode ends because the no-progress ("stuck") detector fires or because it truncates on the step/timeout limit (`max_steps`), the step reward does **not** include `collision_penalty`. A unit test on `compute_reward` / the env step asserts that a stuck-cut / timeout step reward equals the non-collision reward (time penalty + any airborne bonus + progress), with **no** −`collision_penalty` term.
2. **Genuine collisions still eat the full penalty.** A real floor / ceiling / out-of-bounds contact (raw `state.collided` true, and not a controlled dock) still applies `collision_penalty` and still terminates, byte-for-byte as before this UC. A test asserts a floor/ceiling crash reward is unchanged (includes −`collision_penalty`) and `terminated` is true.
3. **Grounded-detector cut is a deliberate, documented choice.** The UC-36 grounded detector (armed only after takeoff, per UC-37) fires when a *previously-airborne* drone drops back and rests on the floor. Whether that cut keeps the collision penalty (it represents a drone that fell) or is also decoupled (consistency with the stuck cut) is chosen and **documented** by the dev-team/challenger, with the rationale recorded in code comments and the plan. A test pins whichever behavior is chosen. (Default recommendation: keep the grounded cut penalized — a post-takeoff drop to the floor is a failed flight — but decouple only the no-progress/timeout cut; the dev-team may argue otherwise.)
4. **Termination signals unchanged.** Decoupling affects only the reward magnitude, not control flow: a stuck/timeout cut still ends the episode (`terminated` or `truncated` per today's semantics) and still reports its reason in `info`. `info["collided"]` / the reported termination reason must not falsely claim a floor/ceiling collision for a no-progress cut. A test asserts the episode still ends on the stuck cut and that `info` reflects "stuck"/"timeout", not "crash".
5. **Positive survival gradient restored (arithmetic bound).** With the shipped constants, the total return of an episode that takes off and stays airborne for the full no-progress window before being cut is **strictly greater** than the return of an episode that sits on the floor for the same duration before being cut. A test asserts `return(hover-then-stuck-cut) > return(sit-then-stuck-cut)` (i.e. the survival bonus is no longer cancelled by the terminal penalty).
6. **Loitering still loses to completing (ordering preserved).** The maximum return achievable by taking off and loitering/hovering without completing the course (bounded by the stuck cut) remains **strictly less** than the return for validly completing the course. A test asserts `max loiter return < completion return`, so the change does not create a hover-forever local optimum — consistent with UC-37 AC-6 and the user's "don't favor loitering over gates" intent.
7. **Floor-shortcut ordering preserved.** A trajectory that dives through the floor to reach the finish still scores strictly worse than a valid completion (it eats a genuine `collision_penalty` via AC-2 and never earns `completion_bonus`). The UC-03 reward-ordering guarantee is retained. A test covers it (or the existing one still passes).
8. **Exploration bump.** `TrainConfig.ent_coef` default changes from `0.0` to `0.01` (documented), to sustain exploration during takeoff discovery. Existing training-config tests are updated to the new default with the change explained. (If the dev-team judges a different small value better-justified, it documents the choice; the default must be > 0.)
9. **Determinism & backward compatibility.** Same seed → identical reset, placement, and (for airborne-start / genuine-crash paths) identical trajectory and reward. Any golden fixture whose recorded reward legitimately changes *because* a stuck/timeout cut no longer includes the penalty is regenerated with the change explained (not silently deleted); airborne-crash and completion fixtures stay byte-identical. All three CI gates green (`uv run ruff check .`, `uv run ruff format --check .`, `uv run --extra dev pytest`). README/docs updated to describe that no-progress/timeout truncation is penalty-free while genuine crashes are not.

## Potential Pitfalls & Open Questions
- **Risk (core coupling)** — the single line in `racing_env.py` that does `if early_termination is not None: crash = True` is what conflates the no-progress cut with a collision. The fix must split "stuck/timeout cut" (no penalty) from "grounded-after-takeoff cut" (penalty per AC-3) rather than blanket-removing the fold, or genuine post-takeoff floor drops stop being penalized.
- **Edge case** — a drone that is *simultaneously* genuinely colliding (raw `state.collided`) AND hits the stuck window on the same step must still eat the penalty (the real collision dominates). Order the logic so a genuine collision always wins over the decoupled stuck cut.
- **Risk (fixtures)** — several golden rollouts likely end on a stuck/grounded cut and will change reward by exactly `collision_penalty`. These must be regenerated deliberately (like UC-37's uc08 baseline), and the change explained; airborne-crash/completion fixtures must NOT change.
- **Assumption** — `info` currently reports the termination reason; AC-4 assumes it (or an equivalent field) exists to distinguish "stuck"/"timeout" from "crash". If it does not, add a minimal reason field rather than overloading `collided`.
- **Open question (AC-3)** — grounded-cut penalization is intentionally left to the dev-team with a documented default (keep it penalized). The challenger pins it against the survival-gradient math so a post-takeoff drop is still discouraged but a peaceful airborne timeout is not.
- **Risk (ent_coef)** — bumping `ent_coef` changes training dynamics broadly; scope it to the default only, keep it small (0.01), and ensure no test hard-codes 0.0 in a way that hides regressions.

User, 2026-09-20, after pulling `main` (UC-37 merged) and retraining on the k1 slice: TUI shows `iters 4/162`, `ep_rew` ≈ −105 flat, `ep_len` ≈ 101, `success` 0%, but — unlike before UC-37 — `entropy`/`std` are now *falling* and `explained_var`/`value_loss` improving (the policy is converging, no longer diffusing). Diagnosis (confirmed in code): the drone sits/does-not-progress, the no-progress detector cuts it at 100 steps, and that cut is folded into `crash=True` → full −100 `collision_penalty`, giving −105 identical to a real crash; the −100 swamps the +10 airborne survival differential so takeoff never out-scores sitting, and with `ent_coef=0` exploration collapses first. User chose the fix: **decouple the stuck/timeout cut from the crash penalty** (genuine floor/ceiling/OOB crashes keep −100), pairing it with a small `ent_coef` bump.
