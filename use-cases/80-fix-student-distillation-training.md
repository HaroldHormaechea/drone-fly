# Use Case 80: Fix the student distillation training (on-policy relabelling / PPO fine-tune / β schedule)

## Summary
UC-79 established that the UC-77 MLP student's ~0% course completion is **not** an observation gap: even `teacher_full` (the student handed the entire 150-value teacher observation) reached only ~1% held-out `macro_completion` versus the teacher's 17.1%, and supplying full gate poses fixed heading (out-of-bounds 44% → ~3%) but converted failures into collisions/floor strikes rather than completions. The bottleneck is the **distillation setup** — compounding error once the DAgger β anneals to 0 (the student drifts to states it was never trained on) plus an action-matching loss that does not optimise trajectory/completion success. This use case retargets the distillation training to lift held-out `macro_completion` to **≥5%**, run as an **ablation of three interventions**, each measured independently against a baseline (the current UC-77/79 distillation): **(1) on-policy DAgger relabelling** — the frozen teacher labels the states the *student* actually visits during student-driven (low-β) rollouts, directly countering the covariate shift; **(2) a PPO fine-tune** of the distilled student against a gate-passage/completion reward instead of pure imitation; **(3) a gentler/longer β schedule** so student-driven rollouts still receive teacher correction. Scope stays MLP-student on the obstacle-free `student-liftoff-open` config, reusing UC-77/79's held-out + Infinity-Loop evaluation, outcome breakdown, an equal **1.8e7**-step budget per run, a resumable back-to-back driver, and a comparison table + recommendation in `docs/experiments/`. It is pure GPU training/evaluation in the batched simulator and needs no Liftoff; it runs in-sandbox on the RTX A3000 exactly as UC-79 did.

## Acceptance Criteria
1. Each intervention is **opt-in via config**, defaulting off, so with every new field unset the behaviour is **byte-identical to UC-77/79**: the student obs dim and schema version, `config.yaml` snapshots, student sidecars, and exports are unchanged, and the existing tests still pass. Suggested fields (final names at the dev-team's discretion): `distill.on_policy_relabel` (bool), `distill.ppo_finetune` (bool / sub-block for steps + reward), and β-schedule parameters extending the current schedule.
2. **On-policy DAgger relabelling**: when enabled, during student-driven rollouts the frozen teacher is queried on the states the *student* visits and those (state, teacher-action) pairs are added to the training target. A test asserts the relabelled targets come from the teacher evaluated on student-visited states (not teacher-visited states).
3. **PPO fine-tune**: when enabled, after (or in place of) imitation the student is optimised with PPO against a gate-passage/completion reward. The reward definition is documented. A test asserts the PPO path runs one update and changes the policy.
4. **β schedule**: the schedule is parameterised so a gentler/longer anneal (more teacher correction on student-driven rollouts) can be configured; the baseline schedule is the current one, unchanged by default.
5. **Ablation runs**: a **baseline + one run per intervention** (4 runs total), all MLP-student on `student-liftoff-open` (obstacles none), equal **1.8e7**-step budget, evaluated with the UC-77/79 `final_report`: held-out `macro_completion` and Infinity-Loop completion, each with exact and noise perception, plus the outcome breakdown (collision/floor/out-of-bounds/gate_lost/timeout), **32 episodes, seed 1234**.
6. A **resumable, unattended driver** (e.g. `scripts/uc80_distillation_fix.sh`) runs the 4 runs back-to-back; a reboot resumes the interrupted run rather than restarting the sequence. Runnable on any CUDA machine with no Liftoff, needing only the repo + the teacher run + the noise model (+ track cache), with the exact artifact paths documented.
7. `docs/experiments/uc80-distillation-training-fix.md` contains **one comparison table** — rows: teacher, baseline, the three variants, and the UC-77 + UC-79 (`teacher_full`) numbers as reference; columns: the AC5 metrics — and ends with a **recommendation**: which intervention(s) move held-out completion, and the next lever if none reach the bar.
8. **Success criterion**: at least one variant reaches **≥5% held-out `macro_completion` (noise)**, decisively above the baseline's noise floor. If none do, the doc records the negative result and names the next lever (e.g. denser reward, longer budget, combined interventions) rather than silently passing.
9. **Unit tests** cover: config plumbing + default-off byte-identity (snapshot/sidecar/obs unchanged); the relabelling target source (AC2); the PPO-reward wiring (AC3); the parameterised β schedule (AC4); and a CPU 1-iteration smoke train for each new path.

## Potential Pitfalls & Open Questions
- **Risk** — PPO against a sparse gate-passage reward may not learn within the equal 1.8e7-step budget. If PPO underperforms, the doc must flag undertraining (as UC-79 did) rather than concluding the method fails; a denser shaped reward or a longer budget may be needed as a follow-up.
- **Risk** — on-policy relabelling increases teacher queries per step and can slow the rollout; keep within the VRAM/throughput envelope observed in UC-79 (peak ~1.6 GB, ~68k env-steps/s single-lane on the A3000).
- **Assumption** — the existing frozen teacher (`teacher_it1374`) is valid to query on off-distribution student-visited states; it is already used that way in DAgger, so this is low-risk.
- **Edge case / Open question** — "gentler/longer β schedule" needs concrete parameters; the exact anneal (end β, horizon, shape) is left to the dev-team analyst to propose from the current schedule and record in the plan.
- **Assumption** — MLP-student scope only (matching UC-79); applying the winning intervention(s) to the K1 connectome actor is a separate follow-up.
