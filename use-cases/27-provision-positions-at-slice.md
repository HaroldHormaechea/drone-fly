# Use Case 27: Provision neuron positions at slice time (not every training run)

## Summary
Neuron 3-D positions used by recording/playback (UC-05/06) and the MRI heatmap (UC-12) are currently provisioned lazily inside `ActivationRecorder.__init__` → `provision_positions()` (`src/drone_fly/record/coordinates.py`) on **every** recording-enabled training run, with no caching. When no anatomical soma coordinates are found it falls back to a dense O(n³) spectral eigendecomposition (`np.linalg.eigh`) over the full connectome — the code itself warns this is slow above 6000 neurons, and the full MaleCNS connectome is far larger — so each `record: true` run redundantly re-fetches anatomy and/or recomputes the layout. (Verified: this runs once in the main process, not per SubprocVecEnv worker, so UC-26's parallel backend is unaffected; and `provision_positions()` does not cache its result.) This UC moves position provisioning to **slice/artifact-creation time** so training only ever *loads* precomputed positions. The `prune` command (`_run_prune_export`, which calls `save_connectome(pruned, cfg.out)`), the `fetch-connectome` base download (UC-14), and the `prune-trained` step each provision positions once when they write their connectome artifact. **Real anatomy is the default, tokenless:** the primary anatomy source is the connectome's own meta CSV — the MaleCNS download already fetches `mcns_all_neuron_meta.csv`, whose `somaLocation` column holds the real neuPrint MaleCNS 8 nm-voxel soma positions (CC-BY) for every neuron that has a soma. Provisioning reads `somaLocation` for the artifact's `bodyid`s from that meta CSV **before** any network call, persists it as the `<stem>_soma.csv` sidecar, and writes the resulting layout as a `<stem>_positions.csv` sidecar beside the artifact. `NEUPRINT_TOKEN`/neuPrint remains an optional fallback for anatomy absent from the meta; the dense spectral eigendecomposition is demoted to a **last-resort** fallback only for neurons/connectomes with no `somaLocation` at all. Because each sidecar lives next to the exact artifact (with the exact neuron-id set) it belongs to, a pruned subcircuit can never pick up the full connectome's positions. Training-with-recording then loads the sidecar (no fetch, no eigendecomposition); if a connectome has no sidecar yet (older artifact, or sliced before this feature), training **self-heals** — it computes the layout once, persists the sidecar, and never pays the cost again. Scope is coordinate-provisioning/artifact infrastructure only: no change to training dynamics, observation schema, connectome graph, reward, or checkpoints; recording-disabled runs are untouched; and the hermetic CI path stays green and offline (neuPrint guarded/mocked, tiny fixtures compute+cache fast).

## Acceptance Criteria
1. **Slice provisions positions (primary):** after the `prune` command writes the pruned connectome (`save_connectome` in `_run_prune_export`), it provisions positions once and writes a `<stem>_positions.csv` sidecar beside the pruned artifact (and, when anatomy was fetched, a `<stem>_soma.csv` sidecar). Verified by running the prune export and asserting the sidecars exist and cover the pruned neuron-id set.
2. **fetch-connectome provisions positions:** the base auto-downloaded connectome (UC-14) gets its positions provisioned/persisted as sidecars when it is fetched, so a non-pruned/full-connectome recording run has positions ready without training-time compute.
3. **prune-trained provisions positions:** the post-training activation-pruning step (UC-07) provisions positions for the subcircuit artifact it produces, with its own sidecars keyed to its own node set.
4. **Training only loads (fast path):** a recording-enabled training run against a connectome that has a valid positions sidecar performs **no** eigendecomposition and **no** neuPrint fetch — assertable via a spy/mock on `_spectral_embedding` / `_load_from_neuprint` (called zero times).
5. **Self-heal fallback:** a recording-enabled run against a connectome with **no** sidecar computes the layout once, logs a warning that it is provisioning on the fly, writes the sidecar, and a subsequent run against the same connectome then takes the fast load path (no recompute).
6. **Real anatomy fetched once and persisted:** when `NEUPRINT_TOKEN` is present, anatomy is fetched and written to `<stem>_soma.csv`; later provisioning/loads reuse the sidecar via the existing tier-2 path with no further network calls. neuPrint is preferred over the spectral fallback.
10. **Real anatomy from the connectome meta CSV (primary, tokenless):** provisioning reads the `somaLocation` column of the connectome's meta CSV (the already-downloaded `mcns_all_neuron_meta.csv`, or the pruned artifact's meta) for the artifact's `bodyid`s as the **primary** anatomy tier — ahead of the `DRONE_FLY_SOMA_CSV`/existing-sidecar/neuPrint tiers, and far ahead of spectral. With no token and no network, a freshly fetched or pruned MaleCNS artifact yields **real** soma coordinates for every neuron that has one, written to `<stem>_soma.csv`. Anatomy precedence order is documented. **Anatomically soma-less neurons** (peripheral sensory afferents whose cell bodies are outside the brain volume) are flagged missing and handled by the partial-anatomy fill — never faked. The dense spectral eigendecomposition runs only when a neuron/connectome has no `somaLocation` anywhere. Verified: a prune/fetch on a fixture whose meta carries `somaLocation` produces a `<stem>_soma.csv` with the real coordinates and triggers **zero** neuPrint calls and no spectral for the soma-bearing neurons (spy/mock).
11. **Full connectome gets real anatomy without the giant eigendecomposition:** because the meta CSV supplies real somas for the full connectome's soma-bearing neurons, `fetch-connectome` provisions real anatomy directly and does **not** attempt a dense `eigh` over ~161k neurons; only genuinely soma-less neurons remain unresolved (partial-anatomy fill), and the large-connectome refuse cap still guards any residual spectral attempt.
7. **Correct node-set binding (no stale reuse):** positions loaded for a connectome must cover that connectome's exact neuron-id set; a sidecar whose id set does not match the loaded connectome is treated as a miss and recomputed, never applied to the wrong neurons. A different connectome or pruned subcircuit never reuses another's positions.
8. **Positions unchanged vs today:** for a given connectome and anatomy-availability state, the positions produced are identical to the current implementation's output (this UC only relocates/caches the computation; the spectral embedding stays deterministic). Verified by comparing a loaded sidecar to a fresh compute.
9. **Scope containment + CI:** no change to training dynamics, observation schema/width, connectome graph, reward, or checkpoints; `record: false` runs never provision (unchanged). Full suite (`ruff check .`, `ruff format --check .`, `uv run pytest`) stays green and never hits the network; sidecar path/format and the fallback are documented (README/config as applicable).

## Potential Pitfalls & Open Questions
- **Edge case (partial anatomy)** — neuPrint may return coordinates for only some neurons; the remainder must be filled deterministically (e.g. spectral for the missing ones) without length mismatch, and the persisted sidecar must record which strategy covered which neurons.
- **Edge case (stale/corrupt sidecar)** — an unreadable or wrong-length sidecar must be detected and safely recomputed, never crashing the run or applying wrong-length positions (ties to AC-7).
- **Assumption** — positions are visualization layout only (viewer coordinate file, MRI heatmap); no training/eval numerics depend on them, so relocating their computation cannot change learning outcomes.
- **Risk (full-connectome spectral cost at fetch-connectome)** — a spectral fallback on the full MaleCNS connectome is very expensive; for the base connectome real anatomy (neuPrint) is strongly preferred, and if neither a token nor anatomy is available the fetch step should warn clearly rather than silently burning a huge eigendecomposition (the analyst pins whether fetch-connectome defers to self-heal in that specific no-anatomy case).
- **Assumption** — sidecars are written next to the connectome artifact; the writing step has permission to write there (it just wrote the artifact itself, so this holds for prune/fetch/prune-trained).

## Original Description
From the user (diagnosed in the root session): training with recording enabled re-requests anatomical soma coordinates and recomputes a dense spectral eigendecomposition over the full connectome on every run, because positions aren't cached. Asked how to fix, the user chose "cache + fetch real anatomy," then refined the design: **"Can't we calculate them when doing the slice, not training?"** — i.e. provision neuron positions as part of the connectome-slicing/pruning step that produces the artifact, so training only loads them. Verified: provisioning happens in `provision_positions()` (`record/coordinates.py`), called from `ActivationRecorder.__init__` via `train/loop.py` after `build_vec_env`; it runs once in the main process (not per SubprocVecEnv worker — UC-26 clean) and does not cache. The `prune` command writes its artifact via `save_connectome(pruned, cfg.out)` in `_run_prune_export` (`cli/__init__.py:443/481`) — the natural provisioning hook.

- Q: When neuPrint is queried for real anatomy, persist it as the `<stem>_soma.csv` sidecar?
  A: **Yes** — persist as the sidecar so training, the MRI heatmap, and the viewer reuse it offline with no repeated network calls.

  A: No — coordinate-provisioning/artifact infrastructure only; positions are visualization layout; recording-disabled runs unaffected; existing checkpoints valid.
